# Local UI and saved View extensions

Optional Linux/Wine extension. The normal upstream tool set is retained. No console-plugin deployment is required.

`gma3_views`, `gma3_store_view`, `gma3_recall_view` and `gma3_assign_view_button` use existing structured bridge operations. They act in the current user profile, not a data pool. Store is create-only and requires explicit screens. By default Store and Recall compare actual native window rectangles and nested persisted settings using view.content. verify_contents:false explicitly requests metadata-only verification. Failed or ambiguous Handle reads make coverage incomplete; hidden raw Handle values use qualified Edit-role resolution. Runtime GridLine caches are disclosed exclusions, while scroll position and camera references remain compared. Assignment verifies the referenced View address and requires `replace:true` for an occupied different assignment. Syntax comes from the bundled 2.5.1 manual's `keyword_view`, `keyword_viewbutton`, `ok_screen` and `wvm_store_recall` topics.

`gma3_ui` and `gma3_ui_click` are registered only when the server permits Lua, and require the console's Lua opt-in. They use the live `GetDisplayByIndex`, `GetUIObjectAtPosition`, `GetTopModal`, object UI/geometry methods and `Mouse` API. Reads have bounded traversal. A click takes explicit UI coordinates, `exclusive:true`, and the complete expected point-target identity and rectangle from a fresh read. Identity/modal/geometry are checked again after mouse movement. Dialogs are refused in favor of `gma3_dialog`. Delivery and application-effect verification are separate; uncertainty never retries, and release is best effort if the chunk is interrupted. Bridge input/control admission still applies to Lua.

`gma3_screenshot` and `gma3_window` are optional and register only when `GMA3_LOCAL_UI_HELPER` is an absolute configured helper path. The adapter is invoked through `/usr/bin/python3` with fixed action/width arguments, without a shell or caller-selected output path. It must return bounded JSON. PNG data, dimensions, aspect, chunks and checksums are checked before returning an MCP image. Window mutations share the mutation lock and report uncertainty after a helper error.

A separately installed helper at a configured path such as `/absolute/path/to/local-ui.py` must use a validated Wine-window selector. The workstation-specific helper is not bundled with this source release. It captures only the main app window and rechecks its identity afterwards. Hidden pixels may be a last-rendered frame; use console state to establish an operation's effect. Missing `DISPLAY`/`XAUTHORITY` variables are restored from the launcher's private `desktop-session.json`, which contains those two paths only and is refreshed each launch.

UI coordinates and physical image pixels can differ. Convert using the current `gma3_ui.bounds` and returned screenshot width/height; never assume a fixed desktop scale. Local live checks observed 2048×1280 UI units versus 3072×1920 physical pixels.

Tests: `test/views.test.ts`, `test/ui.test.ts` (including generated Lua execution), and `test/localui.test.ts`. The [qualification summary](../qualification/2026-10-30.md) records observed deployment scope and unresolved areas. This extension does not qualify arbitrary GUI actions or hardware operation on Wine.

`gma3_view_contents` reads complete saved or current native configuration without recalling it. `gma3_bind_camera_view` binds an explicit Window3D to an exact Camera and can create a new saved View witness; its hashes cover settings, not rendered pixels. Screenshot results carry capture times, validated window IDs and PNG SHA-256; renderer freshness remains unverified.
