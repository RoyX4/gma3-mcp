# Actual stored cue data and fixture diagnosis

`gma3_native_cue_data` reads one sequence without selecting fixtures, starting playback or changing the programmer. The bridge passes actual CuePart handles to `GetPresetData`; converting a negative internal CuePart address back into an ordinary object reference is invalid on the qualified MA version and is deliberately avoided.

The response includes native coverage, a SHA-256 content fingerprint and reconstructed sequence-owned absolute/relative layers with their source cue and part. `include_raw:true` retains the exact observed normalized and raw channel JSON strings. Native release flags remain distinct from zero and missing values. Phaser steps and preset source identities are retained.

Content fingerprints use the `native-json-v2` structural comparison described in [checkpoint integrity](checkpoint.md#stored-integrity-and-native-comparison). JSON key presentation does not change the hash; array order, typed native table keys, unknown data and every value do. Node24 preserves exact encoded numeric lexemes, including integers beyond JavaScript Number precision. Malformed JSON, duplicate keys and bounds failures are refused. Canonical comparison does not replace the original raw data returned by `include_raw:true`.

Tracking No resets inherited layers at each cue. Tracking Yes inherits omitted layers. Cue Release clears previous layers before applying the cue's new hard data. Tracking Distance ends inclusively at an absolute cue number or at the source cue plus the native `Δ +N` offset. After expiration, a temporary value restores its most recent still-valid predecessor or disappears. With confirmed Allow Duplicates, the highest actual part number wins separately for each layer. Temporary distances on competing part layers, unknown distance formats and unreadable part identities make reconstruction incomplete. Break and Shield can protect future edits by changing what gets stored. Assert, playback priority, fades, masters and merges affect playback output.

The maintained bridge captures a bounded native snapshot and returns pages of up to 200 cue objects. Each page is checked against the snapshot's identity, order and coverage. Pages belong to the same connection, expire and are released after reading. The capture supports up to 10,002 objects including internal cues, 50,000 parts and 32 MiB of encoded data. Capture time and serialization also have bounds. Reconstruction materializes at most one million effective cells across the chain. Large and dense sequences can hit different bounds. Older bridges retain the 500-object read limit.

The native reader checks context before and after reading. This detects a generation/show/profile switch, but it cannot atomically exclude an operator's edits. Durable jobs additionally compare native owned state after Store and retain dependency/content fingerprints for resume. A fingerprint proves equality of the observed covered data, not physical light or the winning playback.

`gma3_diagnose_fixture` collects one explicit fixture/cell's identity, available attributes, selection, programmer, output, Grand Master and relevant universe routes. Optional sequence/executor fields add expected playback evidence. Each finding is either directly observed or labelled a possible contributor. An ungranted universe has unavailable output; it is never interpreted as zero. A sampled programmer zero is not proof that it wins output arbitration. Missing readers and coverage remain visible.
